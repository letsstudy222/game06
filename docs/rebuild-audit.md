# Dawn Island presentation rebuild — audit

## Stack and retained logic

HTML/CSS, native ES modules, Canvas 2D; no new framework. Keep normalized keyboard movement, collision substeps, skill cooldown/projectile hit tests, pause/blur handling, game-state boundaries and island registry. Replace the procedural presentation, geometry prop art, small player rendering, fixed surrounding layout and long gameplay instructions.

The previous island had no suitable production environment asset pack. Trees/rocks/bushes were geometric raster primitives, and the map was generated by a paint routine with random scatter. These are replaced rather than recolored.

## Visual production plan

Create original clean environment art with four authored zones and clear routes; create transparent prop masters for depth/collision; create a Phoenix master atlas referenced to the provided mature form, then inspect alpha isolation and register safe source rectangles/anchors before runtime use. Never use a labeled concept sheet or raw irregular grid as a finished atlas. Document remaining asset limitations after inspection.

## Target boundaries

`IslandScene` composes assets and depth; `AssetLoader` owns loading/failure; `Camera` owns smooth follow and pixel snapping; `PlayerPhoenix` owns control/HP; `AnimationController` owns pose selection; `SkillSystem` owns combat; `GameState` owns shrine interaction; `UIHud` displays actual state. Island data holds regions, collider geometry, prop placement and shrine location. No farming, economy, NPC, inventory, new islands, or quest system.
